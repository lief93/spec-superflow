# Overload modules

## R2D contract

This lane owns `tests/modules/overloads/` and this document. Production output
needs no demonstrated change: ownership uses canonical IDs while imports use
the emitted `EtsSymbol.name`. There is no output renaming, alias or dispatch pass.

Main's shared contract appends `EtsFunction.sourceName: String? = null` and the
final `etsFunctionSymbol` argument `sourceName: String = name`. Function/symbol
names are emitted names; IDs retain original source names and source spans.
The validator checks duplicate root IDs before constructing maps, and duplicate
same-kind member IDs. Existing emitted-binding lookup followed by canonical ID
and signature checks validates the target; it does not resolve Kotlin overloads.

Language owns official `NameTable<IrSimpleFunction>` allocation, reserves all
source bindings and uses fixed source order for minimal fresh names. This typed
fixture receives already-allocated names; it does not test or implement that
allocator. Each source overload group is wholly inside one file or final class.
Splitting a source overload group across files is explicitly deferred. Cross-file
callers import several overloads from one owner, plus distinct owner groups with
nonconflicting emitted bindings.

## Finite fixture

Five source modules:

- `Numbers`: `select` and `select_1` have distinct canonical source identities
  and bodies despite both having `(number) => number` target signatures.
  `select_2(left, right)` tests arity. Unique source `select_0` is retained and
  occupies the first candidate suffix; all three overloads originate here.
- `Texts`: `render(string)` and `render_0(number)` form a separate owner group;
  unique `unchanged(value: TokenModel)` preserves its spelling and model identity.
- `OverloadMethods`: non-inherited instance `choose` overloads, unique
  `choose_0`, and existing static method forms with disambiguated names. There is
  one ordinary constructor, not a constructor overload or companion adaptation.
- `TokenModel`: accepted generic-heritage declaration reused read-only and
  included in the input snapshot.
- `OverloadCalls`: thirteen wrappers retain exact source-global/member IDs,
  receiver form, ordered argument symbols and emitted import names.

Checks cover exact imports, file objects/spans, sourceName-derived IDs,
unchanged parameter names and unique bindings, identical-target-signature source
overloads, and both flat/module printer paths. Reversing files preserves bytes;
reversing declaration order preserves imports without reallocating input names.
No runtime `typeof` selection or imported member-name alias appears.

Nineteen negatives require exact `InvalidTarget.source` before runtime selection:
duplicate root/member IDs; stale declaration sourceName; unknown/wrong global ID;
stale global name/signature; unknown/wrong member ID; stale member name/signature;
instance-via-class and static-via-instance receivers; extra value argument;
wrong result; hidden overload; hidden model; duplicate emitted declaration; and
cross-owner import collision. The last is malformed allocated target input,
not a request for an output alias or split-source-group allocation.
