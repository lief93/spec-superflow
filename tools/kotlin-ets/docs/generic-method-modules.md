# Generic method modules

## R2C boundary

This lane owns `tests/modules/generic-methods/` and this document. No production
output gap is demonstrated: `Modules.kt` already traverses method signatures,
method bounds and explicit call type arguments by source declaration identity.
No shared target, language, UI, printer or runtime code is edited here.

Existing target nodes suffice. Main's hierarchy-only `sameMethodSignature`
compares method-owned binders positionally after class substitution, including
exact upper bounds, parameters and results. Canonical `EtsMember` signatures and
IDs remain exact; alpha-equivalence must not make arbitrary call-site binders
valid. Calls instantiate method binders only after receiver/class substitution.
Main also owns rejection of extra type arguments on nongeneric source members.

## Finite fixture

Eight ordinary source modules preserve declarations, source spans and parameters:

- `TokenModel`, `Readable`, `Holder`: accepted generic-heritage declarations reused
  read-only and included in the input snapshot.
- `MethodPort<C>`: generic interface methods `echo<M>`,
  `readBound<R extends Readable<C>>`, and `readChain<R, S extends R>` with the
  same source-owned bound on `R`.
- `MethodBase<C>`: interface implementations with independent `Value`, `Reader`
  and `Item` binders; ordinary `plain`; body-empty bound-only `accept`; and
  argument-free `acceptType<Only>`.
- `MethodDerived`: base instantiated with `TokenModel`, explicit super
  construction, and generic overrides with independent `Output`, `View` and
  `Element` binders.
- `MethodCalls`: direct, base, interface, bounded-receiver, chained-bound and
  inherited calls with explicit model/string/number method arguments. Receiver
  and argument references retain identity and order; bodies use no casts or
  external call symbols.
- `TypeCalls`: `TokenModel` occurs only as an explicit method type argument,
  independently proving its import without a parameter/result/bound reference.

Assertions cover exact import lists, source-file object identity, emitted names
and parameter names, distinct method binder IDs, canonical member signatures,
original argument order, deterministic module ordering and no alias/member imports.
The bound-only method independently introduces the `TokenModel` import into
`MethodBase`; its other methods use the class parameter `C`.

Eighteen negatives retain exact `InvalidTarget.source` and require rejection
before runtime selection: unknown override ID, method binder arity, changed bound,
changed result, changed parameter, class-binder capture, wrong member ID,
alpha-renamed call-site signature, missing/excess method arguments, violated method
bound, wrong call result, wrong value argument, nongeneric member type arguments,
hidden bound, unknown bound ID, hidden type-argument-only declaration, and
conflicting same-named type import. No aliases are introduced to avoid rejection.
