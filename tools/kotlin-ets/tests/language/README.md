# Language slice

Run from the repository root:

```sh
node tools/kotlin-ets/tests/language/run.mjs
node tools/kotlin-ets/tests/language/typed.mjs
node tools/kotlin-ets/tests/language/accessors.mjs
python3 -B tools/kotlin-ets/tests/integration/test_cli.py
node tools/kotlin-ets/tests/ui/run.mjs
node tools/kotlin-ets/tests/language/sdk.mjs
```

The language runner uses the public `kotlin-ets --mode language --out FRESH.ets
SOURCE.kt` CLI, the real Kotlin 2.1.20 frontend, and DevEco's TypeScript runtime.
It never parses Kotlin source or supplies synthetic IR. Every invocation writes
its command, exit status, stdout, stderr, and target into a fresh `.work/run-*`
directory. The exported target functions are executed against independent literal
oracles; unsupported cases must report source offsets and create no target.

The five executable fixtures cover source names, named-call evaluation order and
formal parameter mapping, default argument holes, class fields and mutation,
data-class copy/destructuring/toString, captured lambdas, while/do-while,
break/continue, returns, string concatenation, String type operations, and lazy
singleton initialization/shared state. Eight negative fixtures cover external
constructors, returns crossing an emitted expression closure, the core's reserved
helper namespace, an unknown external call with an external result type, and
overloaded source methods that would otherwise replace one another on target,
unsupported decimal/object string formatting, and delegated properties.

`accessors.mjs` additionally compiles `AccessorSlice.kt` with Kotlin/JVM and the
public ETS CLI, then compares eighteen input cases. It covers computed getters,
custom setters (including early return), backing-field access, a default getter
paired with a custom setter, initialization without invoking a setter, and
single evaluation of a side-effecting receiver, compound assignment and
post-increment. Source property names and the
setter parameter name are checked on the generated target AST. The SDK runner
also compiles this fixture as an ETS module without editing generated bytes.

Loop coverage is language execution, independent of the UI's repeat adapter:
`LanguageSlice.kt` lowers actual `IrWhileLoop`/`IrContinue` nodes and computes a
sum of 8; `ControlSlice.kt` lowers `IrDoWhileLoop`/`IrBreak`, stops at 3, and its
captured Unit callback produces 7. General `for` iterator/range calls and
`kotlin.repeat` require call rules not supplied by this language slice.

## Interface

`LanguageLowering(diagnostics, rules)` implements the shared `Language` interface.
Types, expressions, statements, functions and classes return structured target
nodes, never target text. The core owns exports, target validation and printing.
Arithmetic calls go through the supplied typed rules. A scope's
`callRule` is consulted before registered rules or source-declaration fallback.
Adapter expression results must be assignable to the mapped Kotlin call type.
`CallRule.lowerStatement` applies only to discarded calls and calls under implicit
Unit coercion; storing or returning an unsupported external value cannot use it.
Ordinary source calls use their resolved declaration and parameter slots.
Source functions/classes use declaration-derived target symbols, including the
declaration's actual file, not the caller's file. Only implicit `this` uses an
external reference in language lowering. Bindings use IR symbols; source names
are preserved. Compiler temporary aliases
retain their original expressions for UI adaptations, while emitted bindings
ensure ordinary expression reads do not repeat evaluation.

`typed.mjs` compiles the public lowerer with the real official frontend and target
validator, independently of UI/stdlib adapters. Its two Kotlin source fixtures
check parameter/local symbol identity, cross-file function and singleton symbol
resolution, missing-declaration rejection, explicit default slots, adapter
precedence and invalid result rejection. Effect tests cover direct statement
calls and implicit Unit coercion, while stored/returned external values reject
with source spans. It supplies adapter nodes, not synthetic Kotlin IR.

The architecture migration retains the twelve public CLI oracles unchanged.
The effect-boundary behavioral RED is `.work/typed-WFioQt`: official compilation
succeeded and the missing discarded-call adaptation rejected `Instant.now`.
No native SDK/device verification has been rerun for the typed migration; the
SDK evidence below belongs to the preceding string-emitter implementation.
Statement-position assignments currently retain redundant Unit-discard IIFEs;

## Bounded support

Data-class generated `copy`, components and `toString` use their actual IR bodies.
Generated equality/hashCode are not emitted; attempts to call them are rejected.
Ordinary source objects use a private constructor and a lazy shared instance;
cyclic object initialization is not covered. Inheritance, nested classes/companion
objects, secondary constructors, overloaded methods, delegated/extension properties, generic source
declarations, suspend methods, runtime boxed numeric/Char discrimination, and
non-local returns across lambda/expression boundaries are outside this slice.
Custom member accessors on simple classes and objects are supported as described
above; they are not generalized delegation support.
Long-typed declarations are unsupported; precisely representable Long constants
are accepted for the UI color adapter. Unknown external calls and constructors
never fall back to plausible target names. Float/Double/Long/collection and
ordinary-object interpolation without a source `toString` implementation is
rejected rather than using target coercion.

## Actual SDK compilation

`sdk.mjs` clones an isolated host under `/private/tmp`, runs the public CLI for
the five original positive Kotlin fixtures plus accessors and official
concatenation lowering, and copies the generated ETS bytes unchanged.
`SdkIndex.ets` imports and calls all seven modules. The runner executes installed
DevEco `ohpm install` and `hvigorw assembleHap --mode module -p
module=entry@default -p product=default --no-daemon`. It asserts that all seven
modules appear as ETS inputs in the SDK's `CompileArkTS` `filesInfo.txt`, that a
HAP and ABC were produced, and that original/copied generated hashes and Kotlin
source hashes did not change. Compiler implementation hashes must also remain
unchanged throughout this run. There are no device calls.

Set `KOTLIN_ETS_SDK_SEED` to another compatible local host if the default readonly
run-07 host is unavailable. To compile accepted generated bytes without invoking
the Kotlin CLI again, pass the directory containing the five `*.kt.ets` files:

```sh
node tools/kotlin-ets/tests/language/sdk.mjs tools/kotlin-ets/tests/language/.work/run-gNGEis
```

The accepted `run-gNGEis` modules passed the actual SDK build in
`/private/tmp/kotlin-ets-language-sdk-vTp4aQ` (exit 0). Full stdout/stderr, hashes,
host, compiler cache and signed HAP are retained there. No generated-language
errors occurred; the sole warning was the test host's exception-capable
`stage.loadContent` call. No LanguageEmitter change was needed. This adds target
validity for the five bounded fixtures, not device execution or broader Kotlin
coverage.

Fresh CLI generation plus the compiler-input/HAP assertions also passed in
`/private/tmp/kotlin-ets-language-sdk-mtnTR6`. All five newly generated modules

contains the five compiler records, generated/source hashes and ABC/HAP hashes;
`sdk-assemble.stdout`, `sdk-assemble.stderr` and `sdk-filesInfo.txt` retain the
exact SDK evidence. Installed ETS SDK metadata: version `6.1.1.125`, API `24`;
the cloned run-07 product retains its target/compatible SDK `6.0.0(20)` profile.
